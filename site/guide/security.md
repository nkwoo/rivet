# 보안

Rivet은 서버 신원 확인을 건너뛰는 옵션을 두지 않습니다. 대신 처음 볼 때 확인하고, 바뀌면 막습니다.

## SSH 호스트 키

- 처음 접속하는 서버는 키 유형과 SHA-256 지문을 보여 주고 승인을 받습니다. 서버에서 `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub`로 확인한 값과 비교하세요.
- 승인한 키는 Rivet의 known_hosts에 저장합니다.
- 저장된 것과 다른 키를 받으면 **연결을 차단**하고 저장된 지문과 받은 지문을 함께 보여 줍니다.
  서버를 다시 설치한 경우처럼 변경이 정상이라면, 서버 관리자에게 확인한 뒤 **저장된 키 검토**에서 기존 항목을 지우고 다시 연결합니다.
- 점프 호스트를 거칠 때도 단계마다 따로 검증합니다.

## RDP · FTPS 인증서

- RDP는 처음 접속할 때 서버 인증서 지문을 확인하고 고정합니다(TOFU).
- FTPS는 운영체제가 신뢰하는 인증서면 그대로 연결하고, 자체 서명 등 신뢰하지 않는 인증서는 지문을 확인한 뒤 고정합니다.
- 고정한 인증서와 다르면 연결을 차단합니다. 상단 막대의 방패 아이콘(**저장된 호스트 키와 인증서**)에서 고정 항목을 검토하고 지울 수 있습니다.

## 비밀번호와 패스프레이즈

- 저장을 선택한 경우에만 macOS 키체인 / Windows 자격 증명 관리자에 저장합니다.
- 연결 목록 데이터베이스, 설정 파일, 로그에는 기록하지 않습니다.
- 인증에 성공한 경우에만 저장해서, 틀린 비밀번호가 남지 않습니다.

## 파일 전송

- 원격 파일 이름이 대상 폴더 밖(`../`, 절대 경로)을 가리키거나 Windows 예약 이름이면 내려받지 않습니다.
- FTP 명령에 들어가는 경로·사용자명·비밀번호에 줄바꿈(CR/LF)이 있으면 보내지 않습니다.
- 서버 목록과 응답에는 크기 상한을 둡니다.
- 평문 FTP는 경고를 계속 표시합니다.

## 앱

- 웹뷰는 앱에 들어 있는 화면만 띄우고 원격 페이지를 불러오지 않습니다.
- 업데이트는 앱에 들어 있는 공개 키로 서명을 확인한 뒤에만 설치합니다. [업데이트](./updates) 참고.
- 릴리스 파일은 GitHub Actions에서 빌드하고 빌드 출처 증명을 붙입니다. [내려받은 파일 확인](./install#내려받은-파일-확인) 참고.

## 취약점 신고

보안 취약점은 공개 이슈로 올리지 말고, GitHub 저장소의 **Security → Report a vulnerability**로 신고해 주세요.
자세한 내용은 [SECURITY.md](https://github.com/nkwoo/rivet/blob/main/SECURITY.md)에 있습니다.
