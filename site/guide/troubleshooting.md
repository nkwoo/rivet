# 문제 해결

## 호스트 키가 바뀌었다고 연결이 막힘

서버가 Rivet에 저장된 것과 다른 호스트 키를 보냈습니다. 서버를 다시 설치했거나 키를 바꿨을 수도 있지만, 누군가 연결을 가로채고 있을 수도 있습니다.

1. 서버 관리자에게 키를 바꿨는지 확인합니다.
2. 정상이라면 상단 막대의 방패 아이콘(**저장된 호스트 키와 인증서**)에서 해당 서버의 항목을 지웁니다.
3. 다시 연결해 새 지문을 확인하고 승인합니다.

RDP, FTPS 인증서가 바뀐 경우도 같은 방법으로 고정 항목을 지웁니다.

## 인증에 실패함

- 비밀번호를 다시 입력하라는 창이 나오면 비밀번호를 확인합니다. 저장된 비밀번호가 틀렸다면 연결 편집의 **저장된 비밀 값 삭제** 후 다시 입력합니다.
- 개인 키: 서버의 `~/.ssh/authorized_keys`에 공개 키가 있는지, 키 파일 경로가 맞는지 확인합니다.
- ssh-agent: 에이전트에 키가 들어 있는지 `ssh-add -l`로 확인합니다. Windows는 **서비스**에서 **OpenSSH Authentication Agent**가 실행 중이어야 합니다.
- 점프 호스트를 거치는 경우 "점프 호스트 인증 실패"면 점프 호스트 쪽 인증을 확인합니다.

## 키체인에 접근하지 못함

macOS에서 키체인 접근 허용 창이 나오면 **허용** 또는 **항상 허용**을 누릅니다. 거부했다면 비밀번호를 연결할 때마다 입력해야 합니다.
업데이트 후 다시 물을 수 있습니다([업데이트](./updates#직접-설치) 참고).

## FTP 목록이나 전송이 안 됨

"서버의 데이터 포트에 연결할 수 없습니다"는 FTP 패시브 모드의 데이터 연결이 막혔다는 뜻입니다.

- 서버 방화벽이나 공유기에서 패시브 포트 범위가 열려 있는지 확인합니다.
- Docker나 포트 포워딩을 쓰면 패시브 포트를 **같은 번호로** 함께 열어야 합니다. 제어 포트(21)만 열면 로그인은 되지만 목록·전송이 실패합니다.
- 가능하면 SFTP를 쓰세요. 포트 하나로 동작합니다.

## RDP가 느림

- 툴바의 **진단**으로 fps와 입력 지연을 확인합니다.
- 연결 편집에서 **고해상도(Retina)**를 끄거나 해상도를 낮추면 전송량이 줄어듭니다.
- 아직 H.264 코덱을 쓰지 않아 동영상처럼 화면 전체가 계속 바뀌면 공식 클라이언트보다 느릴 수 있습니다.
